# 시스템관리자 (System Admin) — 메뉴 명세 (DRAFT v0.2)

> **Role**: `SYS_ADMIN` (현 `ADMIN` 의 시스템 영역)
> **앱**: `admin-web` 내 별도 영역 (`/admin/system/**`)
> **현행 구현**: 없음 (모두 신규)

## 역할 정의

학원 운영자와 분리된 IT 관리자. 권한·메뉴·코드 등 시스템 메타데이터, 로그·감사, 환경설정·백업을 담당.
일상 운영(회원·주문·강의) 데이터에는 원칙적으로 접근하지 않음 (최소 권한).

## 검토 필요 (사용자 의견 요청)

1. **운영자 vs 시스템관리자 경계**
   - **회원관리**: 운영자가 일반 회원 관리 / 시스템관리자가 운영자·강사 권한 부여 — 이 분리 OK?
   - **메뉴 관리**: 시스템관리자만 OK?
2. **감사 로그 범위** — 어떤 행위를 감사 대상으로 할지 (결제 변경·환불·권한 변경 우선?)
3. **메뉴 동적화 시점** — 메뉴를 코드 하드코딩(현재) 유지 vs DB 기반 동적 관리로 전환 (Sprint 우선순위?)
4. **백업 권한** — 시스템관리자가 백업 생성·복원까지 / 복원은 별도 결재?
5. **운영자 행위에 대한 시스템관리자 알림** — 중요 작업 시 알림 발송 정책?

## 레거시 잔재 검토

해당 영역은 신규이므로 레거시 잔재 없음. 단, 신규 구현 시 다음 표준 준수:

- **공통 코드 테이블**: `acm_common_code_grp` / `acm_common_code` 형태로 신설 (ADR-005 prefix 규약)
- **감사 로그**: `acm_audit_log` (행위자·대상·전후값·timestamp·IP)
- **메뉴 마스터**: `acm_menu` (parent_id·order·role_code·icon·to)

## 백엔드 매핑 (제안)

- 신규 경로: `/api/sysadmin/**` → `hasRole("SYS_ADMIN")`
